# BUG-006：Microsoft Store 初始化失败阻碍桌面应用更新

## 1. 日期、状态与范围

- 发生日期：2026-10-10。
- 本机状态：**当时商店访问恢复，应用更新完成并核验安装包版本发生变化**。
- 官方修复状态：未确认。
- 分类：应用更新依赖受本机商店网络隔离影响，不把它写成已确认的独立 Codex 更新器缺陷。

## 2. 我在做什么，期望与实际结果

我点击桌面应用左下角的更新重启，感觉没有成功。排查显示应用确实重启，但版本没变；接下来需要通过 Microsoft Store 检查更新。

我打开商店后，窗口一直加载，后来出现初始化失败提示，无法顺利继续更新。商店恢复后我看到 ChatGPT 显示“即将完成”，最终报告更新完成。我还误下载了 ChatGPT Classic，这属于更新过程中的名称理解偏差，不另计产品故障。

## 4. 现场触发条件

1. 我点击应用的更新重启。
2. 应用重启后版本未变化；检查工具提示需要 Windows Store 检查安装资格／更新。
3. 我打开 Store，窗口一直加载。
4. 缓存重置后仍加载，随后可见初始化失败页面。
5. 添加商店访问本机代理的例外并重新打开后，我确认商店已打开；之后完成应用更新。

没有在干净环境独立复现，也没有单独测量整个下载／安装流程的各阶段耗时。截图中的“即将完成”不能单独作为失败证据。

## 5. 原始错误与证据

页面必要错误片段：

```text
Microsoft Store 初始化失败。请尝试刷新或稍后返回
```

当时读取的商店日志最小片段：

```text
0x80072EFD
无法与服务器建立连接
连接尝试失败。 (127.0.0.1:7897)
```

同一本机代理从普通命令行访问商店服务器能收到 HTTP 响应；当时商店不在本机网络访问例外列表。原始日志中的设备及账户信息不公开。

## 6. 尝试与实际结果

| 尝试 | 结果 | 说明 |
|---|---|---|
| 点击应用更新重启 | 进程重启，版本仍未变化 | 不能宣布新版本已安装，也不能仅凭此定位更新器根因 |
| 检查相关 Windows 服务 | 服务正在运行 | 未支持“服务全部停掉”的判断 |
| 使用 `wsreset.exe` 重置商店缓存 | 进程退出；我仍报告一直加载 | 重置未解决现场问题 |
| 普通程序通过本机代理访问商店服务器 | 有 HTTP 响应 | 代理服务能到达该服务器；不证明受隔离的商店也能访问本机代理 |
| 给 Microsoft Store 添加专用 loopback 例外 | 验证列表出现商店；我随后确认商店能打开 | 与日志和普通程序对照一起，支持本机访问隔离是这次商店失败的重要原因 |
| 通过商店完成更新 | 我报告完成；安装包版本从旧值变为新值 | 支持本机更新已完成，不代表其他应用功能一并恢复 |

排查中有一次命令参数写法错误，以及一次非管理员执行被拒绝。这些是操作问题，不是商店或 Codex 产品故障。之后经系统管理员确认执行成功，没有关闭整个 Windows 防火墙。

## 7. 已确认原因与未确认部分

- **本机证据支持的原因：**商店连接本机代理超时，缺少访问本机网络的例外；添加该应用专用例外后恢复。
- **未确认：**为什么这个例外之前不存在、应用内更新提示与 Store 之间的全部内部行为、是否有长期回归。
- 我不把“普通重启没让版本变化”直接归因为更新器 bug；同一过程中商店不可用是已经查到的实际阻碍。

## 8. 修改与验收

实际添加的例外仅针对 `Microsoft.WindowsStore_8wekyb3d8bbwe`。重新打开商店后，我明确确认能打开，并随后确认完成更新；本机包版本检查支持更新结果。

没有卸载 Codex、清空所有系统网络设置或为所有应用开放本机网络。重启或更新的成功不能代替其他功能的验收。本记录只标注商店访问与应用更新已在当时恢复。

## 9. 我希望改进的地方

我希望更新提示能明确区分“已重启”“正在等待商店”“更新已安装”，并在商店网络不可用时给出可操作的诊断。新版应用与 Classic 并存时，也希望名称和更新页面能清楚说明我应该更新哪一个，减少误下载。
