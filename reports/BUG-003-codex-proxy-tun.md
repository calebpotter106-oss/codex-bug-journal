# BUG-003：原来仅用规则模式能使用，后来登录与连接依赖 TUN

## 1. 日期、状态与问题范围

- 最早发生日期：未记录。我记得在 Plus 到期后重新订阅，再登录 Codex 时出现了问题；这个先后顺序不能证明订阅造成故障。
- 留存排查日期：2026-10-07。
- 本机状态：当时 Clash 运行并开启 TUN 后可以使用；**关闭 TUN、仅靠普通系统代理的完整解决方案未解决**。
- 官方修复状态：未确认。
- 相关记录：BUG-004 是后来出现的账户／设置访问验证异常，不应把它的 403 原因倒推为这次最初登录错误的原因。

## 2. 我当时在做什么，期望与实际结果

我从普通图标启动 Codex，希望像以前一样，只用代理软件的规则模式即可登录和继续使用。我重新订阅 Plus 后遇到了登录错误，按照网上建议打开虚拟网卡后能够登录。后来一度关闭虚拟网卡也能使用，但隔了几天重新打开，应用再次要求登录，不开虚拟网卡时又失败。

我也遇到过登录成功后关闭虚拟网卡，继续使用 Clash 普通代理仍然断联，重新开启虚拟网卡后恢复。切成全局模式也没有解决我当时描述的连接问题。这让我无法确定是订阅、登录状态、启动方式还是网络路径出了变化，也让我需要一直开着虚拟网卡。

## 4. 现场触发条件与复现边界

我的使用经历可以描述为：普通图标启动 → 应用要求登录 → TUN 关闭时登录／连接失败 → 开启 TUN 后可以使用。登录后关闭 TUN 也曾引起断联。

**没有在干净环境重新安装或独立复现完整的订阅、登录流程。**留存了同一份已有登录凭据的网络对照，但它验证的是账号请求和路径，不是完整客户端冷启动登录。

## 5. 原始错误与最小证据

最初登录弹窗的原始错误全文：**未记录**。不能用后来其他事件的错误替代。

后续网络探测保留了以下结果：

```text
TUN 开启：已有凭据的账号请求 → HTTP 200
TUN 关闭，直接请求同一接口：error = timeout（7 秒界限）
TUN 关闭，显式指定本机代理：HTTP 200
```

另一次连接探测的最小错误片段：

```text
curl: (28) Connection timed out after 5005 milliseconds
```

现场连接记录把桌面进程与后台进程的连接匹配到 `Tun` 入口，目标包括 `chatgpt.com` 与 Codex 云端地址。原始身份数据、连接标识和完整配置不随本记录公开。

## 6. 我尝试过什么，实际说明了什么

| 尝试 | 实际结果 | 能说明什么／不能说明什么 |
|---|---|---|
| 打开 TUN | 我的登录／连接恢复；账号接口请求成功 | 当时这个网络路径可用，不证明最初为什么发生变化 |
| 仅切换全局模式 | 我报告仍然不行 | 全局模式不能强制所有程序进入代理 |
| 关闭 TUN，并打开 Windows 实际系统代理进行对照 | ChatGPT／Codex 云端直连探测仍超时 | 至少被测试的请求未因系统代理开关而自动获得可用路径 |
| 同一凭据经显式代理请求 | HTTP 200 | 代理通道与当时已有凭据能完成该账号请求 |
| 检查旧的 `ChatGPT-Codex-Proxy.cmd` | 文件和目标应用路径有效，普通图标启动未携带该脚本参数 | 我没有从普通图标获得脚本注入的设置；旧脚本当前完整效果仍未复验 |

旧脚本用于以前的电脑与手机 Remote 连接，设置环境代理和 Chromium 代理参数。我报告它后来不再解决当前问题，但本次没有完全退出客户端再用它做端到端验收，所以不能把“脚本所有功能都失效”作为已证明结论。

最初自编代理探测有连接实现错误，修正后才采用上述账号对照数据。这是排查工具问题，不是 Codex 错误。

## 7. 已确认、推测与待验证

- **已确认：**当时直接网络路径与代理路径结果不同；TUN 可接管已观察到的后台流量。纯系统代理未覆盖所有被测试连接。
- **排查时判断：**应用某些独立后台／WebSocket 请求没有可靠使用普通系统代理。安装文件的只读检查与现场路径支持这一解释，但它不是官方确认的根因。
- **未确认：**Plus 重新订阅是否触发故障、哪次更新引入变化、直连失败涉及的全部 DNS／路由原因。
- **额外观察：**代理软件配置显示启用系统代理，而 Windows 实际开关一度为关闭。造成不一致的原因未确认，不把它单独认定为根因。

## 8. 实际修改与验收

短暂对照测试后恢复了原网络状态，保留 TUN 开启。另创建了恢复连接启动器，检查代理端口、开启 TUN、发起应用启动请求；没有替换旧脚本，没有改登录凭据或应用安装包。

启动器在已有应用实例运行时通过了检查并发起启动，没有完成退出后的冷启动验收。我的实际可用方式是开着 Clash 和 TUN 使用普通图标。

**这是一种本机可用方式，不是“普通系统代理问题已彻底修复”，也不是官方已修复。**后续代理节点和配置有变化，本记录不保证当前仍完全一致。

## 9. 我希望产品改进的地方

我希望桌面应用能明确显示哪些后台连接采用系统代理、环境代理或直连；登录错误能区分账号无效、网络超时和 WebSocket 连接失败。最好提供覆盖后台连接的统一代理设置，避免我只因普通图标启动或某个后台请求不遵循系统代理，就必须开启影响全机流量的 TUN。
