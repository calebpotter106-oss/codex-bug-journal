# BUG-002：Chrome 扩展显示已安装，但本机通信宿主缺失

记录日期：2026-10-12。平台：Windows。状态：本机修复后验收通过；缺失的安装原因与官方修复状态未确认。

## 我遇到的问题

Codex 的“电脑操控”设置中，Google Chrome 显示绿色的“已安装浏览器扩展程序”，按钮是“管理”，开关已经开启。管理页也显示“已安装”，相关权限已允许。

但是自动控制 Chrome 时一直收到：

```text
Browser is not available: chrome
```

我按照设置里的“重新安装扩展程序”完成安装。Chrome 能打开欢迎页，扩展已启用，但侧边栏最初仍提示安装桌面应用。点击“open the app”可以打开当前桌面应用，因此协议启动能够工作，并不能证明扩展的本机通信宿主已配置成功。

我期望“已安装”状态能反映用于自动控制的整条连接是否就绪。至少在宿主缺失时，设置页应显示不同的诊断状态。

## 环境与证据

- 桌面安装包：OpenAI.Codex 26.1007.2314.0。
- Chrome 插件组件：26.1007.21434。
- Chrome 扩展现场版本目录：1.26.901.11451_0。
- 官方扩展已安装、注册并启用。

重新安装后，官方本机诊断仍发现两项缺失：

```text
%LOCALAPPDATA%\OpenAI\extension\com.openai.codexextension.json
HKCU\Software\Google\Chrome\NativeMessagingHosts\com.openai.codexextension
```

Chrome 宿主运行索引当时也没有有效条目。扩展安装诊断通过，宿主诊断未通过，两者的结果存在明显差异。脱敏摘要见 [Chrome 宿主前后对照](../evidence/chrome-host.sanitized.json)。

这些证据确认了本机配置缺失，但没有查明最初是哪一步安装、更新或迁移导致了缺失。我也没有在干净安装环境复现。

## 本机处理经过

我使用当前桌面安装包自带的官方 Chrome 插件与宿主，在用户插件缓存中补齐 manifest、注册项和运行索引。随后通过官方 CLI 安装启用 `chrome@openai-bundled`。

安装时曾因宿主占用插件缓存而出现访问拒绝。处理过程中先备份相关资料，临时暂停这个宿主注册并停止对应宿主进程，完成安装后恢复注册；没有修改应用安装包。

同时处理了 [BUG-001 中的 CODEX_HOME 目录连接问题](BUG-001-windows-browser-junction.md)。最终重新打开应用后，宿主诊断通过，Chrome 侧边栏加载聊天，官方 Browser API 通过网页读取、输入和点击验收。

这是对我的特定安装状态进行的本机修复，不是官方发布的修复方案。由于宿主、插件启用与目录路径调整顺序执行，我没有证据精确拆分每项修改对最终恢复的贡献。

## 我希望产品改进的地方

希望设置页将“扩展已安装”和“本机通信连接已就绪”分别检查。在重新安装流程结束前，最好验证 manifest、注册项、实际宿主程序和握手状态。

如果重新安装只修复浏览器扩展，无法生成或恢复本机宿主，也希望能明确提示。现在“已安装”的界面状态很容易让我以为安装完全正常，从而把问题误判为网络或权限。

本条记录的结果仅表示我的 Chrome 在 2026-10-12 通过验收，不表示这个安装缺陷已在后续版本修复。
